## Цели

### G-01: Простой в настройке и поддержке аналог spec-runner
В spec-runner мешают много вендоров/моделей в конфиге и сложный код. В sdd-codex — один вендор (OpenAI) и один конфиг-файл, код такой, что его легко читать и дорабатывать. «Стало хорошо» — коллега берёт инструмент и пользуется, не разбираясь в вендорах.

### G-02: Работа агента проверяема и неподделываема
Агент не может объявить «готово» на словах: красный тест доказан самим runner'ом, трогать можно только разрешённые файлы, диф проходит ревью до коммита. Эти проверки остаются, даже если добавляют сложности.

### G-03: Видно ход прогона и остаётся след
По ходу прогона в терминале видно, что происходит с каждой задачей; после прогона на диске есть логи и отчёты, по которым можно разобраться, что было.

### G-04: Расход под контролем
Прогон не уходит в бесконечные повторы и не съедает незаметно деньги: ретраи ограничены, стоп по расходу можно включить.

### G-05: Совместимость с готовыми наборами файлов
Спеку, требования и задачи часто готовит другое приложение. sdd-codex должен брать такой готовый набор и выполнять его без переделки — формат тот же, что у spec-runner.

## Функции

### FR-01: Создание спеки из описания программы
**Цели:** G-01, G-05
**Критерии приёмки:**
- описание программы передаётся команде либо текстом в командной строке, либо путём к файлу
- по описанию агент-планировщик создаёт три файла: спеку, требования и задачи
- созданные файлы — в том же формате, что использует spec-runner
**Слова владельца:** спека создается на основе описания программы (в командной строке или берется из файла), при это создаются файлы спеки, требований и задач

### FR-02: Приём готового набора файлов от других приложений
**Цели:** G-05
**Критерии приёмки:**
- если спека, требования и задачи уже есть на диске (сделаны другим приложением), команда запуска выполняет их без шага создания спеки
- runner не требует ничего, кроме этих файлов в ожидаемом формате
**Слова владельца:** формат нужно соблюсти, поскольку часто spec-runner получает готовый нкбор файлов от других приложений, эту программу хочется использовать с такой же целью

### FR-03: Создание спеки и запуск — разные команды
**Цели:** G-01, G-03
**Критерии приёмки:**
- команда создания спеки и команда запуска выполнения — две разные команды
- команда создания спеки не начинает выполнение задач
- выполнение задач стартует только второй командой
**Слова владельца:** 4. создание спеки одна команда, запуск на выполнение - другая

### FR-04: Цикл задачи: тест — код — прогон теста
**Цели:** G-02
**Критерии приёмки:**
- команда проверки берётся из спеки задачи
- перед правкой кода runner сам запускает тест и сохраняет вывод падения
- задача принята только если после правки тот же тест проходит
**Слова владельца:** 4. из спеки. по спецификации создаются задачи, перед запуском задачи пишутся тесты, потом пишется код и потом тесты прогоняются

### FR-05: Замороженные файлы
**Цели:** G-02
**Критерии приёмки:**
- агент может менять только файлы, перечисленные в задаче
- изменение любого другого файла — задача не принята
**Слова владельца:** 3. можно менять только файлы, перечисленные в задаче — остальное заморожено

### FR-06: Гейт код-ревью отдельным агентом
**Цели:** G-02
**Критерии приёмки:**
- перед коммитом диф смотрит отдельный агент-ревьюер на OpenAI, автоматически, без участия человека
- если ревьюер сказал «нельзя коммитить» — задача запускается заново с его замечаниями, и этот запуск считается ретраем
**Слова владельца:** 1. отдельный агент-ревьюер на OpenAI, автоматически; 1. новый прогон задачи с замечаниями ревьюера (и это считается ретраем)

### FR-07: Коммит в текущую ветку
**Цели:** G-02
**Критерии приёмки:**
- после зелёного теста и одобрения ревьюера runner делает коммит в текущей ветке
- runner не создаёт ветки и не открывает PR
**Слова владельца:** 3. только коммиты в текущей ветке

### FR-08: Ретраи и остановка всего прогона
**Цели:** G-04
**Критерии приёмки:**
- после N неудачных прогонов задачи (N из конфига) прогон останавливается целиком
- следующие задачи после остановки не запускаются
**Слова владельца:** 2. повторяет N раз, потом останавливает весь прогон

### FR-09: Лимиты расхода
**Цели:** G-04
**Критерии приёмки:**
- лимит ретраев и стоп по токенам/деньгам на прогон задаются в конфиг-файле
- стоп по токенам/деньгам по умолчанию выключен
**Слова владельца:** 4. лимит ретраев + стоп по токенам/деньгам на прогон. обе позиции настраиваются в файле конфигурации, но по умолчанию "стоп по токенам/деньгам на прогон" не включен.

### FR-10: Один конфиг-файл, один вендор
**Цели:** G-01
**Критерии приёмки:**
- в одном конфиг-файле задаётся модель отдельно для каждого вида задач (планирование, кодинг, ревью)
- в конфиге нет других вендоров, кроме OpenAI
**Слова владельца:** 4. один вендор - OpenAI, один конфиг-файл (с настройкой модели для каждого вида задач)

### FR-11: Прогресс в терминале
**Цели:** G-03
**Критерии приёмки:**
- на запуск каждой задачи печатается строка: номер задачи, её описание, время запуска
- под ней на каждый прогон — новая строка: номер прогона, текущий шаг (написание теста / кодинг / тест) и результат теста, если тест завершился
**Слова владельца:** 4. в терминале на запуск каждой задачи появляется строка с номером задачи и ее описанием + время запуска, под этой строкой статус (номер прогона, написание теста/кодинг/тест - результат теста, если тест завершился), каждый прогон новая строка.

### FR-12: Логи и отчёты на диске
**Цели:** G-03
**Критерии приёмки:**
- на каждую задачу создаётся своя поддиректория с логом на каждый прогон
- в этой поддиректории лежит итоговый отчёт по задаче
- в списке задач проставляется отметка о выполнении
**Слова владельца:** 4. на каждую задачу своя поддиректория содержащая лок на каждый прогон + итоговый отчет по этой задаче + отметки о выполнении в списке задач
