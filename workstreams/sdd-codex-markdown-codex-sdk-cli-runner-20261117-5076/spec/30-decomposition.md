## Проверки

#### BEH-01: Готовый набор spec-runner разбирается своим парсером
Положить рядом `requirements.md`, `design.md`, `tasks.md` в формате spec-runner (заголовки `### TASK-NNN: имя`, статусная строка с эмодзи и без, `**Checklist:**`, `**Depends on:**`, `**Touches:**`, `**Verifies:**`) и разобрать набор. Все задачи, их поля и ссылки на `REQ-NNN`/`DESIGN-NNN` прочитаны; незнакомые строки сохранены и не вызывают ошибки.
- **checked_by**: `kind: pytest` `target: tests/test_format.py::test_parses_ready_spec_runner_set`
**Критерии:** FR-02/2

#### BEH-02: Ошибки формата и зависимостей видны до платных вызовов
Запустить разбор набора со сломанным заголовком задачи, с ссылкой `Depends on` на несуществующий id и с циклом зависимостей. Каждый случай — отказ с именем файла, строкой и id задачи; ни одного обращения к OpenAI не сделано.
- **checked_by**: `kind: pytest` `target: tests/test_format.py::test_reports_format_and_dependency_errors_without_api_calls`
**Критерии:** FR-02/2

#### BEH-03: Модели по роли в одном конфиге, вендора в схеме нет
Прочитать `sdd-codex.config.yaml` с разными моделями для `planner`, `coder`, `reviewer` — каждая роль получает свою модель. Конфиг с ключом вендора/провайдера или любым другим неизвестным ключом — ошибка старта с именем ключа.
- **checked_by**: `kind: pytest` `target: tests/test_config.py::test_models_per_role_and_no_vendor_key`
**Критерии:** FR-10/1, FR-10/2

#### BEH-04: Лимиты задаются в конфиге, стоп по расходу выключен по умолчанию
Прочитать конфиг без секции `budget`: `max_tokens` и `max_usd` — `null`, стоп по расходу выключен, `run.max_retries` взят из файла. Явно заданные `max_tokens`/`max_usd` попадают в настройки прогона.
- **checked_by**: `kind: pytest` `target: tests/test_config.py::test_limits_from_config_budget_disabled_by_default`
**Критерии:** FR-09/1, FR-09/2

#### BEH-05: Описание программы — аргументом или из файла
Вызвать команду создания спеки с описанием позиционным аргументом, затем с `--from-file path.md`. В обоих случаях планировщик получает один и тот же текст описания; без описания и без файла — отказ с подсказкой.
- **checked_by**: `kind: pytest` `target: tests/test_cli_spec.py::test_description_from_argument_or_from_file`
**Критерии:** FR-01/1

#### BEH-06: Команда создания спеки пишет ровно три файла в формате spec-runner
Выполнить команду создания спеки с подставным агентом-планировщиком. В `paths.spec_dir` появились ровно три файла — требования, спека (design) и задачи, — и все три разбираются парсером формата spec-runner без ошибок; расхождение с форматом — ошибка команды, а не молчаливая запись.
- **checked_by**: `kind: pytest` `target: tests/test_cli_spec.py::test_writes_exactly_three_files_in_spec_runner_format`
**Критерии:** FR-01/2, FR-01/3

#### BEH-07: Создание спеки и запуск — две отдельные подкоманды, спека не исполняет
CLI принимает две независимые подкоманды — создание спеки и запуск. После команды создания спеки ни один агент-кодер и ни одна команда проверки не запускались, коммитов нет: команда завершилась сразу после записи файлов.
- **checked_by**: `kind: pytest` `target: tests/test_cli_spec.py::test_spec_command_does_not_execute_tasks`
**Критерии:** FR-03/1, FR-03/2

#### BEH-08: Команда проверки берётся из записи задачи
Задача с готовой командой в `**Test:**` исполняется этой командой; задача со списком селекторов в `**Verifies:**` — командой, собранной по шаблону `verify.selector_runner`. Задача без обоих полей отклоняется с указанием её id, «общая» команда из конфига не подставляется.
- **checked_by**: `kind: pytest` `target: tests/test_verify.py::test_command_comes_from_task_record`
**Критерии:** FR-04/1

#### BEH-09: Красный прогон делает сам runner и сохраняет вывод падения
Прогнать задачу: после шага написания теста runner сам выполняет команду проверки до того, как агент правил код, и вывод падения лежит в `attempt-NN.red.txt` артефактов задачи.
- **checked_by**: `kind: pytest` `target: tests/test_task_loop.py::test_runner_proves_red_before_coding`
**Критерии:** FR-04/2

#### BEH-10: Тест, прошедший на красном шаге, закрывает прогон как провальный
Подсунуть задачу, чья команда проверки проходит сразу после шага написания теста. Прогон закрыт как неудачный, шаг кодинга не начинался, коммита нет, причина записана в лог и отчёт задачи.
- **checked_by**: `kind: pytest` `target: tests/test_task_loop.py::test_green_at_red_step_fails_attempt`
**Критерии:** FR-04/2

#### BEH-11: Задача принята только когда та же команда проходит после правки кода
После шага кодинга runner выполняет ту же строку команды, что и на красном шаге, и принимает задачу только при её успехе. Правка тестовых файлов после красного шага ломает зафиксированный хеш и прогон не принимается; провал команды тоже закрывает прогон.
- **checked_by**: `kind: pytest` `target: tests/test_task_loop.py::test_accepted_only_when_same_command_passes_green`
**Критерии:** FR-04/3

#### BEH-12: Менять можно только файлы, перечисленные в задаче
Прогон, в котором агент изменил ровно файлы из `**Touches:**` задачи (каталог покрывает содержимое) и файлы, названные её командой проверки, проходит проверку заморозки. Задача, не перечислившая файлы, отклоняется с указанием id; изменения в `.sdd-codex/` в проверку не входят.
- **checked_by**: `kind: pytest` `target: tests/test_freeze.py::test_only_task_listed_files_allowed`
**Критерии:** FR-05/1

#### BEH-13: Любой лишний изменённый файл — прогон не принят
Прогон, в котором изменён, создан или удалён файл вне списка задачи (по `git status --porcelain`), не принимается: дерево откатывается по затронутым путям, нарушение с именем файла попадает в лог и отчёт, коммита нет.
- **checked_by**: `kind: pytest` `target: tests/test_freeze.py::test_extra_changed_file_rejects_attempt_and_rolls_back`
**Критерии:** FR-05/2

#### BEH-14: Коммит только в текущую ветку, без ветвления и PR
После зелёного теста, успешной заморозки и вердикта `commit` runner делает один коммит в текущем HEAD с сообщением по `git.commit_template`. Ветка прогона не менялась, новых ветвей нет, `push` и обращений к PR не было; грязное дерево перед стартом — отказ.
- **checked_by**: `kind: pytest` `target: tests/test_git.py::test_commits_to_current_branch_without_branching_or_pr`
**Критерии:** FR-07/1, FR-07/2

#### BEH-15: Отметка о выполнении ставится в самом `tasks.md`
После коммита статусная строка задачи правится на месте (`⬜ TODO` → `✅ DONE`, без эмодзи — `TODO` → `DONE`), остальная строка и файл сохраняются байт-в-байт, правка входит в тот же коммит задачи. Задачи со статусом `DONE` при повторном прогоне пропускаются.
- **checked_by**: `kind: pytest` `target: tests/test_status.py::test_marks_task_done_in_tasks_md`
**Критерии:** FR-12/3

#### BEH-16: Диф перед коммитом смотрит отдельный агент-ревьюер, автоматически
Перед коммитом вызывается отдельная роль ревьюера: своя модель из конфига, чистый thread без истории кодера, на вход — `git diff HEAD`, запись задачи, красный и зелёный вывод тестов. Вердикт — строгий JSON, он лежит в `attempt-NN.review.json`; подтверждения человека нигде не запрашивается, `commit` — единственный путь к коммиту.
- **checked_by**: `kind: pytest` `target: tests/test_review.py::test_reviewer_is_separate_automatic_agent`
**Критерии:** FR-06/1

#### BEH-17: Вердикт `block` перезапускает задачу с замечаниями и считается ретраем
Ревьюер вернул `block` с замечаниями (или нераспознанный ответ): прогон закрыт без коммита, замечания попали в промпт следующего прогона, счётчик неудачных прогонов задачи увеличился так же, как от упавшего теста.
- **checked_by**: `kind: pytest` `target: tests/test_review.py::test_block_restarts_task_with_comments_as_retry`
**Критерии:** FR-06/2

#### BEH-18: Запуск исполняет готовый набор без шага создания спеки
В репозитории уже лежат три файла набора (сделаны другим приложением). Команда запуска парсит их и начинает исполнять задачи: планировщик не вызывался, файлы набора не перезаписывались. Исполнение не начиналось до этой команды; отсутствующий или неразбираемый набор — отказ с именем файла, без попытки «досоздать» его.
- **checked_by**: `kind: pytest` `target: tests/test_run_command.py::test_runs_ready_set_without_planning_step`
**Критерии:** FR-02/1, FR-03/3

#### BEH-19: После N неудачных прогонов задачи прогон останавливается целиком
Задача с `run.max_retries: N` из конфига проваливается N раз (провал теста, нарушение заморозки, `block` ревьюера и сбой агента равноправны). Прогонов задачи ровно N, после этого runner остановил весь прогон.
- **checked_by**: `kind: pytest` `target: tests/test_runner.py::test_stops_whole_run_after_max_retries`
**Критерии:** FR-08/1

#### BEH-20: После остановки следующие задачи не запускаются
При остановке по исчерпанным ретраям ни одна последующая задача не стартовала: в сводке прогона они помечены `not started`, код выхода ненулевой. Уже закоммиченные задачи отмечены `DONE`, повторный запуск продолжает с места остановки.
- **checked_by**: `kind: pytest` `target: tests/test_runner.py::test_following_tasks_not_started_after_stop`
**Критерии:** FR-08/2

#### BEH-21: Стоп по токенам/деньгам срабатывает только когда включён в конфиге
С заданными `budget.max_tokens`/`max_usd` расход суммируется по usage каждого вызова (деньги — по `prices_per_mtok`) и при превышении прогон останавливается с причиной `budget`. С лимитами `null` прогон не останавливается, но накопленный расход всё равно записан в `run.jsonl` и сводку.
- **checked_by**: `kind: pytest` `target: tests/test_budget.py::test_budget_stop_only_when_configured`
**Критерии:** FR-09/1

#### BEH-22: На запуск задачи печатается строка с id, описанием и временем
При старте задачи в терминал выводится ровно одна строка с её номером (id), описанием и временем запуска.
- **checked_by**: `kind: pytest` `target: tests/test_progress.py::test_prints_task_start_line`
**Критерии:** FR-11/1

#### BEH-23: На каждый прогон — своя строка с номером, шагом и результатом теста
Под строкой задачи на каждый прогон появляется новая строка: номер прогона, текущий шаг (`написание теста` / `кодинг` / `тест`) и, когда команда проверки завершилась, её результат в той же строке. Без TTY каждая смена шага печатается отдельной строкой с тем же набором сведений; поток вывода агента в терминал не попадает.
- **checked_by**: `kind: pytest` `target: tests/test_progress.py::test_prints_line_per_attempt_with_step_and_result`
**Критерии:** FR-11/2

#### BEH-24: У каждой задачи своя поддиректория с логом на каждый прогон
После прогона с несколькими попытками есть `<artifacts_dir>/<run-id>/<TASK-id>/` с `attempt-NN.log` на каждый прогон (промпты, ответ агента, вывод команд), рядом `attempt-NN.red.txt` и `attempt-NN.review.json`; ключ OpenAI в логах замаскирован.
- **checked_by**: `kind: pytest` `target: tests/test_artifacts.py::test_per_task_dir_with_log_per_attempt`
**Критерии:** FR-12/1

#### BEH-25: В поддиректории задачи лежит итоговый отчёт
В той же поддиректории есть `report.md` с командой проверки, списком разрешённых файлов, шагом и причиной провала по каждому прогону, вердиктами ревьюера, коммитом и расходом. Отчёт записан и при успешной задаче, и при провальной.
